# 运行日志与本地诊断

[主页](../README.zh-CN.md) · [English](diagnostics.md)

从 v0.9.2 开始，GameDevUsageBar 在运行期间保存有容量上限的日志，用来区分主动退出、Windows 会话结束、已记录的异常，以及没有记录到结束的会话。这是本地诊断功能，不会增加上传器、自动更新、系统服务或自动重启守护进程。

## 日志位置

```text
%LOCALAPPDATA%\GameDevBar\logs
```

为兼容已有数据，继续使用 `GameDevBar` 这个目录名。日志包含 UTC 和本地时间，并使用会话 ID 区分各次运行。当前文件为 `runtime.jsonl`，轮转片段为 `runtime.1.jsonl` 至 `runtime.4.jsonl`。最多保留五个日志文件，每个最多 1 MiB，合计约 5 MiB，另有一个很小的会话状态文件。轮转会删除最早的日志片段，不会修改账户设置、余额或保存的登录信息。

如果 Windows 拒绝写入或磁盘不可用，诊断摘要会显示日志不可用。无法落盘的事件不会被宣称为已经保存；日志写入失败本身也不能可靠解释后续退出。

## 事件含义

| 事件 | 能说明什么 |
| --- | --- |
| `app_start`、`app_ready` | 新进程已启动，并且初始化已经进入就绪状态。 |
| `handled_exception` | 某项操作失败，程序已经处理了错误；不等于进程崩溃。 |
| `startup_exception` | 初始化时发生异常。 |
| `dispatcher_unhandled`、`appdomain_unhandled`、`winforms_unhandled` | 异常到达界面或进程级处理入口，需结合后续退出事件及原因判断是否导致进程结束。 |
| `task_unobserved` | .NET 报告某个后台任务发生错误；仅凭这一条不能断定程序退出。 |
| `exit_requested`、`app_exit`、`session_end` | 已记录的退出请求或结束过程；原因字段说明程序观察到的退出路径。 |
| `session_ending` | 程序收到 Windows 会话结束通知。 |
| `previous_session_incomplete` | 下次启动发现上次会话没有完成结束记录，具体原因未知。 |
| `resource_sample` | 该进程的内存及相关资源采样。 |

已知退出原因包括 `tray_exit`（托盘退出）、`overview_exit`（总览退出）、`tray_popup_exit`（托盘用量面板退出）、`session_shutdown`（Windows 关机）、`session_logoff`（Windows 注销）、`startup_failure`（启动失败）和 `fatal_exception`（致命异常）。关闭总览或隐藏悬浮窗不会退出托盘进程。无法记录退出路径时，原因会保持未知，不会直接归因于用户、杀毒软件或缓存。

`previous_session_incomplete` 可能来自强制结束、断电、系统故障，或程序在最终记录写入前就结束。它不能证明是谁关闭了程序，也不能证明具体原因。突然终止时，程序无法执行自己的异常与退出处理；缺失的采样或结束记录属于证据限制，不能当作诊断结论。

## 排查内存与缓存增长

程序运行时，每 60 秒采样一次资源使用量，包括进程内存、托管内存信息、线程与句柄数量，以及有边界的缓存大小统计。采样不会把缓存响应正文读入日志；程序退出后，也不会留下独立的后台监控。

应比较同一会话内连续的采样。持续增长的内存占用可以支持进一步排查泄漏，但一次较高的读数不能证明泄漏或内存耗尽。磁盘缓存大小与进程内存是不同的指标，小缓存也不能排除内存问题。采样失败会记录错误，不会伪造成零。

## 导出诊断包

1. 在托盘菜单选择 **导出诊断信息…**，或在总览选择 **导出诊断信息**。
2. 查看当前 JSON 摘要，包含程序版本、运行与日志状态、安全的服务状态和时间，以及本地额度 API 状态。
3. 选择 **保存诊断 ZIP…** 并选定新的本机文件名，已有压缩包会被保留。ZIP 包含经过过滤的 `diagnostics.json`、`runtime-summary.json`、有数量上限的 `recent-events.json`，以及已知的运行日志。只有明确保存才会写出诊断包，不会上传。

界面测试或没有运行日志组件的会话会提供 **保存诊断 JSON…**。预览会说明日志不可用，不会把仅含 JSON 的导出称为完整日志包。

导出不包含账户配置、缓存余额、凭据、本机 CLI 登录文件或数据目录内的任意其他文件。异常记录保留异常类型与方法调用栈，不记录异常消息、源文件路径、HTTP 请求头、响应正文、Token 或 Cookie。摘要仍会暴露有哪些服务、哪些服务失败，以及请求时间；自行分享之前应检查诊断包。

## 覆盖范围

这些记录从 v0.9.2 开始保存，无法还原之前没有日志的退出。即使已开启日志，突然结束进程或电脑仍可能只能在下次启动时识别为未完成会话，具体原因保持未知。
