A compact Windows bar for AI quotas, API credits, and balances. This release includes the reliability and account-switching improvements made since v0.9.1.

## Changes since v0.9.1

- **Diagnostics (v0.9.2):** bounded startup, exit, error, and resource logs, plus an explicit local diagnostic ZIP export. Interrupted sessions are reported without inventing an exit cause. A logging failure is shown separately from app/API readiness; exports omit credentials and native auth files.
- **Settings preservation (v0.9.3):** unreadable account or presentation settings stay intact and read-only instead of being treated as a new installation and overwritten with defaults. A genuinely absent file is handled separately.
- **Popup placement (v0.9.4):** opening a provider popup no longer stages the visible window at the monitor's top-left. Layout updates use the latest anchor and refit after DPI changes.
- **Popup account switching (v0.9.5):** **Switch account** appears beside Refresh and Settings. For Codex and Claude, it restores a saved CLI auth document through the guarded switcher, verifies the result, and then selects that account for display. The header dropdown remains display-only; API-provider footer buttons also change display selection.
- **Clear switch outcomes:** the currently displayed saved account remains selectable because the CLI may use a different login. Progress, BUSY, read-only, and unresolved results are reported. Known read-only settings are rejected before native auth changes, and an unresolved auth write is not automatically repeated.
- **Updated homepage screenshots:** the floating bar, hover details, and clicked provider popup are shown with synthetic sample data, in English and Chinese.
- **Display polish:** the overview footer follows the built version, and a single reset ticket uses the correct English singular.

The existing tray, customizable featured modules, nine provider adapters, reset countdowns, network MB/s, transparency controls, multiple-account storage, current Claude OAuth renewal, and read-only local quota API remain available.

## Upgrade

Choose **Exit** from the tray before upgrading. Setup preserves the existing account/settings data in `%LOCALAPPDATA%\GameDevBar`; saved credentials and presentation preferences are not part of the installer payload.

CLI switching requires closed CLI sessions and a saved login. Existing desktop sessions are unaffected. The app does not start a CLI, redeem tickets, or use a display-only selection as authorization to change native auth.

## Verification scope

Regression suites cover bounded logging/export, unreadable settings, visible popup positioning, footer menu/event routing, synthetic auth replacement, and rejected writes. Final build, installer, and test results are recorded in [ACCEPTANCE.md](https://github.com/tabztggg/GameDevUsageBar/blob/main/ACCEPTANCE.md); fixture coverage is not proof that every real vendor account can access its usage endpoint.

Local verification passed **176 behavior checks**, **22 WPF/Win32 checks**, **10 footer-switch checks**, **8 popup-position checks**, **7 native-account host checks**, the multiple-account/layout suites, and **8 runtime lifecycle scenarios** with diagnostic-export checks. The isolated English/Chinese installer lifecycle passed **62 checks**. Credentials, account switches, and screenshots used synthetic fixtures.

Provider permissions and private subscription endpoints may change. Optional fields—including reset-ticket inventory—appear only when reported. Gemini AI Studio request counts are not remaining quota; Tripo API credits exclude Studio credits.
