# v0.9.9 — all accounts for the service you hover

2026-10-07 · Windows 10/11 x64 · Preview

Hover Claude, Codex, or another service on the floating bar to compare all saved accounts for that service. The bar keeps one entry per provider; the detail panel uses a compact layout and scrolls for longer account lists. Clicking opens the same account information with actions beside each account.

This release includes the account-login work from the local v0.9.6 and v0.9.7 builds and the multi-account panels prepared in v0.9.8. The v0.9.8 tag was an unpublished staging candidate; it did not provide a public release download.

## Changes since v0.9.5

- **Provider-scoped multi-account details:** each saved account retains its own source, plan, quota windows, reset dates/countdowns, balances, optional reset-ticket count/expiry, freshness, and failure state. Five-hour and weekly quota values appear side by side when returned; missing fields stay unknown.
- **Matching hover and click information:** both use the same account view. The hover panel can be entered and scrolled; clicking adds **Show this account**, supported **Switch CLI login**, **Refresh**, **Settings**, and **Manage accounts** actions.
- **Explicit display selection:** the **Displayed account** badge and **Show this account** action identify the account shown on the bar/overview. Actual CLI auth replacement remains a separate guarded action. Existing sessions are not replaced.
- **Named, isolated Claude accounts:** **Add Claude account** creates an account-specific configuration directory and starts an attended login through a separately installed protected Claude Code Bridge. Renaming preserves the account directory and binding.
- **Fresh Firefox authorization profiles:** each attended Claude authorization uses a new profile and separate browser instance, without importing another profile's cookies, history, cache, passwords, extensions, or session state. The user still chooses the intended account and completes authorization.
- **Scoped auth and recovery:** Claude local-OAuth renewal uses the exact bound profile. Captured auth remains Windows-user encrypted. BUSY, read-only, and unknown results retain their guards; uncertain login, switching, or token-rotation effects are not automatically replayed.
- **Desktop launch and popup checks:** the Explorer launcher supports an existing folder view or the registered desktop view and refuses a command-runner fallback. The position-before-show behavior is retained for the provider popup.
- **Small-screen hover placement:** account panels are constrained to the monitor work area instead of falling behind the taskbar. Placement follows the anchor's DPI and retains an open account list's scroll position.
- **Overflow-menu hover lifecycle:** a hover panel attached to an overflow menu dismisses when that menu closes. Disconnected anchors are refused.
- **Independent test prerequisites:** offline protected-login tests create their own synthetic launcher prerequisites instead of requiring a real user-level Claude Code Bridge installation on the CI runner. This changes test isolation; the production Add Claude account workflow still requires the protected Bridge.
- **English and Simplified Chinese documentation and screenshots** show the compact account comparison and per-account actions.

## Upgrade and compatibility

Exit GameDevUsageBar from its tray menu before replacing app files. Install into the same directory; settings, encrypted accounts, caches, and presentation preferences remain under `%LOCALAPPDATA%\GameDevBar`. Setup does not log into or switch a native CLI account. The default installed path is `%LOCALAPPDATA%\Programs\GameDevUsageBar`.

Existing captured-account configurations use schema 4. An isolated Claude profile uses schema 5 and requires v0.9.6 or later; older versions reject that configuration rather than substituting another login directory. Keep a backup before any downgrade.

**Add Claude account requires a compatible protected Claude Code Bridge installed separately on the same machine, plus its supported CLI and Firefox setup.** It is not a universal sign-in client bundled with GameDevUsageBar. Missing or incompatible prerequisites fail explicitly. The regular tray, widget, overview, and API-account queries do not require that Bridge.

## Validation scope

The source passed 192 behavior checks, 8 native popup-position checks, 22 general WPF/Win32 checks, 13 Claude-account UI checks, and 8 runtime lifecycle checks. Multi-account/native-host, diagnostic-export, and bilingual overview/compact-bar/transparency checks also passed. All 11 provider-hover checks passed, including overflow-menu dismissal. Provider-hover fixtures cover one, two, five, and six saved accounts, independent error states, account selection, shared hover/click information, bilingual text, scroll limits, every available monitor's four corners, and 36 small-work-area/DPI placement cases. Homepage images are actual WPF renders with synthetic accounts.

The isolated English/Chinese installer lifecycle passed 62 checks: installation, payload integrity, shortcut/startup options, upgrade, running-app refusal, uninstall, and retention of synthetic user data. It did not modify the production installation.

These checks do not prove an actual attended Claude authorization, all live vendor endpoints, every physical mouse/DPI scenario, or antivirus approval. 悬停和点击详情采用紧凑的多账号列表：鼠标移到哪个服务，就查看这个服务保存的全部账号；栏上每个服务仍只有一个入口，账号多时滚动。来源返回的 5 小时/周额度并列显示，保留各账号的重置时间、倒计时、积分、重置券到期、时效和独立错误状态。

悬停面板按显示器工作区和实际 DPI 定位，避免小屏幕上的内容越过任务栏边界；重新定位时保留账号列表和滚动位置。溢出菜单关闭时，该菜单的悬停面板同时关闭；拒绝使用已脱离界面的定位元素。
