# 0.9.6 — local Claude account login integration

This build is local. It has not been uploaded or released on GitHub.

**Add Claude account** now requires a display name, creates an independent
`CLAUDE_CONFIG_DIR`, and starts the maintained protected Bridge's attended
subscription login. The user completes Firefox authorization. On confirmed
native closure and a changed credential, the app binds and refreshes only that
slot. Editing a name does not move its directory or change credentials.

Pending same-name accounts are reused after a confirmed failure. Busy and
unresolved attempts block repeated login. Unknown receipts remain preserved,
including after restarting the app; reading a newly saved credential does not
settle that earlier attempt. The existing renewal owner pauses during attended
login and cannot commit against a changed directory or account binding.

Existing account snapshots, API keys, native default logins and the legacy
`%LOCALAPPDATA%\GameDevBar` data directory are retained. Profile configuration
uses schema 5. Older builds must not be used after saving this format.

The button requires this machine's maintained Claude Code Bridge extension,
reviewed native CLI version, protected network route and Firefox profile. It
does not authorize a model call, another renewal owner or an unattended login.

Validation includes synthetic provider isolation and renewal checks, actual
WPF button integration with injected login outcomes, and offline Bridge entry,
native byte-lock and harmless Windows Job transport checks. Real subscription
login and browser interaction still require the user's attended verification.
